# Lab 2.3 — Kernel Image Artifact Audit

## Objective
Distinguish the three primary build outputs of the Linux kernel:
1. `vmlinux`: Non-stripped ELF executable; retains all debugging symbols, section headers, and exact virtual addresses. Used by GDB for kernel debugging and static analysis.
2. `arch/arm/boot/zImage`: Self-extracting compressed boot image. Loaded by QEMU `-kernel`.
3. `System.map`: Symbol lookup table generated by `nm -n vmlinux`. Essential for interpreting kernel oops/panic logs and resolving raw hex addresses to C function names.

## Run Inspection
```bash
bash inspect_artifacts.sh
```

## Key Inspection Insights
- `vmlinux` has entry point `stext` at `0xC0008024` (or `0xC0008000`), well above `PAGE_OFFSET = 0xC0000000`.
- `zImage` is much smaller than `vmlinux` because symbol tables and debug info are stripped and the code payload is compressed.
- `System.map` addresses must exactly correlate with the addresses embedded in `vmlinux`.
