# Lab 01 — MMIO Address Mapping and Volatile Disassembly

## Objective
Inspect how the C compiler translates peripheral struct member accesses into Cortex-M3 memory load/store instructions (`LDR` and `STR`). Prove that `volatile` forces memory accesses and prevents register caching.

## Prerequisites
- P2-M01 completed.
- P2-M02 README Section 2.1 (MMIO Mental Model).

## Environment
- Host: Linux / WSL2 with GNU Toolchain (`arm-none-eabi-gcc`, `arm-none-eabi-objdump`, `gdb-multiarch`).

## Estimated Time
30 minutes.

## AI Mode
**AI-Free**.

## Build
```bash
make clean && make disasm
```

## Procedure
1. Open `build/firmware.asm` and find the function `gpio_init()`.
2. Inspect the instructions setting bits in `RCC->APB2ENR`:
   ```arm
   ldr r3, [pc, #...]  ; Loads 0x40021000 (RCC base address)
   ldr r2, [r3, #24]   ; Loads APB2ENR register (offset 0x18 = 24)
   orr.w r2, r2, #20   ; Sets IOPCEN and IOPAEN bits
   str r2, [r3, #24]   ; Writes back to APB2ENR
   ```
3. Locate the `TIM2->SR` flag clear in `TIM2_IRQHandler()`:
   Observe how the compiler emits an explicit `STR` store instruction.
4. Experiment: Remove `volatile` from `g_tim2_ticks` in `include/timer.h` and recompile with `-O2`. Inspect `main()` disassembly: observe whether the compiler optimizes away the while loop check!

## Expected Observation
- Every access to CMSIS peripheral registers generates an explicit `LDR` or `STR` to memory addresses in the `0x40000000`–`0x5FFFFFFF` peripheral block.
- Non-volatile variables checked in loops are optimized into register comparisons, causing infinite loops when modified by an ISR.

## Actual Verification Status
**VERIFIED** (host toolchain disassembly). Disassembly generated by GCC 13.2.1 confirms explicit load/store sequences.

## Questions
1. Why does CMSIS declare all peripheral struct members with `__IO volatile`?
2. Does `volatile` prevent the compiler from reordering two independent peripheral writes? (Hint: check C sequence points vs hardware memory barriers).

## Failure Modes
- Forgetting `volatile` on ISR-shared variables causes the main loop to cache the old value in a CPU register (e.g. `r4`), ignoring updates from the interrupt.

## Debug Strategy
In GDB, issue `disassemble /m function_name` to view C source lines alongside generated assembly.

## Challenge
Write a minimal C function accessing a non-volatile pointer in a tight loop and compare its disassembly against a `volatile` pointer at `-O2`. Verify that GCC eliminates the loop body for the non-volatile read.
