# P2-M03 Gate Assessment Solution: Seeded TIM_CR1_UDIS Defect

> **Evaluation Authority**: Evaluator & Course Lead Reference  
> **Target Fixture**: `gate/gate_fault_firmware/`

---

## 1. Executive Diagnostic Summary

- **Symptom**: DMA transfer counter `DMA1_Channel1->CNDTR` is stuck at 128. No Half-Transfer (PA3) or Transfer-Complete (PA4) pulses are ever emitted. `TIM3->CNT` is running, ADC1 is powered on and calibrated, and DMA1 Channel 1 is enabled in circular mode.
- **Root Cause**: In `gate_tim3_init()`, `TIM3->CR1` is initialized with `TIM_CR1_CEN | TIM_CR1_UDIS` (`0x03`).
- **Architectural Mechanism (RM0008 Section 14.4.1)**:
  Bit 1 of `TIMx_CR1` is **`UDIS` (Update disable)**:
  - `0`: Update Event (UEV) enabled. An UEV is generated by counter overflow/underflow or setting the `UG` bit.
  - `1`: **Update Event disabled**. The shadow registers keep their values; the counter overflows without generating an update event or update interrupt.
  Because TIM3 Master Mode is configured to emit its trigger on the Update Event (`MMS = 010`), setting `UDIS = 1` completely suppresses all TRGO trigger output pulses! As a result, ADC1 never receives external trigger edges, never initiates regular conversions, and never generates DMA requests.

## 2. Hypothesis Evaluation Matrix

| Hypothesis | Test / Register Evidence | Finding | Conclusion |
|---|---|---|---|
| **H1**: DMA1 Channel 1 clock or enable missing | Check `RCC->AHBENR` bit 0 and `DMA1_Channel1->CCR` bit 0 | Both bits are 1; DMA is enabled and clocked | Disproven |
| **H2**: ADC1 clock, power, or calibration failed | Check `RCC->APB2ENR`, `ADC1->CR2[ADON]`, `RSTCAL`, `CAL` | All bits verified: ADC is powered and calibrated | Disproven |
| **H3**: ADC1 external trigger routing wrong | Check `ADC1->CR2` bits [19:17] (`EXTSEL`) and bit 20 (`EXTTRIG`) | `EXTSEL=100` (TIM3_TRGO) and `EXTTRIG=1` are set | Disproven |
| **H4**: TIM3 clock or counter stopped | Check `RCC->APB1ENR` and `TIM3->CNT` | Timer is clocked and counting | Disproven |
| **H5**: TIM3 TRGO trigger generation suppressed | Inspect `TIM3->CR1` and `TIM3->CR2` | `TIM3->CR1` contains `0x03` (`CEN=1`, `UDIS=1`)! | **PROVEN ROOT CAUSE** |

## 3. Live GDB Diagnostic Commands (EXPECTED / ILLUSTRATIVE)

```gdb
# 1. Inspect DMA transfer counter: confirms no requests arrived
(gdb) p/d DMA1_Channel1->CNDTR
$1 = 128

# 2. Inspect ADC status and trigger control: confirms ADC is armed for TIM3_TRGO
(gdb) p/x ADC1->CR2
$2 = 0x001e0101
# Bits [19:17] = 0b100 (TIM3_TRGO), Bit 20 = 1 (EXTTRIG), Bit 8 = 1 (DMA), Bit 0 = 1 (ADON)

# 3. Inspect TIM3 Master Mode: confirms MMS = 010 (Update)
(gdb) p/x TIM3->CR2 & (7 << 4)
$3 = 0x20
# Bits [6:4] = 0b010

# 4. Inspect TIM3 Control Register 1: reveals seeded defect!
(gdb) p/x TIM3->CR1
$4 = 0x03
# Bit 0 (CEN) = 1, Bit 1 (UDIS) = 1!
```

---

## 4. Minimal Corrective Patch

```diff
--- a/gate/gate_fault_firmware/acquisition_gate.c
+++ b/gate/gate_fault_firmware/acquisition_gate.c
@@ -58,3 +58,3 @@ void gate_tim3_init(void)
-    TIM3->CR1 = TIM_CR1_CEN | TIM_CR1_UDIS;
+    TIM3->CR1 = TIM_CR1_CEN;
 }
```

---

## 5. Verification & Proof
After clearing `TIM_CR1_UDIS`, TIM3 emits update events upon counter overflow every $100\ \mu\text{s}$, driving `TIM3_TRGO` pulses into ADC1. ADC1 executes conversions and triggers DMA1 Channel 1. `DMA1_Channel1->CNDTR` decrements continuously, and PA3/PA4 emit 78.125 Hz milestone pulses.
